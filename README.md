# POS 单店本地收银系统

一个跑在店内一台 Windows 电脑上的收银系统：PC 管理后台 + 手机/自助机收银台，数据只存本机 SQLite，**不需要互联网**，断网照常收银。

---

## 快速开始

1. 双击 `start.bat`
2. 浏览器自动打开 `http://localhost:8080`
3. 进「管理后台」，默认密码 **admin888**（首次登录后到「设置」修改）
4. 后台「商品」页可导入/新增商品；「设备」页可查看接入的收银终端
5. 手机连同一 Wi-Fi，扫后台「设置」页的二维码（或打开 `https://本机IP:8443/pos`），首次进入起个设备名即可收银
6. 需要开机自启：右键 `安装开机自启.bat` →「以管理员身份运行」
7. 手机要**用摄像头扫码**：必须走 `https://本机IP:8443/pos`（安卓 Chrome 在 http 下禁用摄像头），端口被拦时右键 `放行防火墙端口.bat` 以管理员运行

> 需要 JDK 17。`start.bat` 会在缺少 jar 时自动调用 Maven 构建（需联网）。
> 也可以先运行 `build.bat` 构建，再分发整个目录。
> 局域网域名、H3C 路由器固定 IP、安卓 DNS 设置见 [`docs/网络与域名配置.md`](docs/网络与域名配置.md)。

## 手机端地址与 HTTPS（摄像头扫码必读）

| 地址                           | 端口 | 用途                                  | 能否用摄像头                         |
| ------------------------------ | ---- | ------------------------------------- | ------------------------------------ |
| `http://本机IP:8080/pos`     | 8080 | 电脑/浏览器日常使用、扫码枪、手输条码 | 安卓下**不能**（非安全上下文） |
| `https://本机IP:8443/pos`    | 8443 | 手机、自助机收银                      | **可以**                       |
| `https://localhost:8443/pos` | 8443 | 主机本机访问                          | 可以（无需信任证书）                 |

- 证书是启动时**自动生成的自签证书**：`data/tls.p12`（密码 `pos-local`，别名 `pos`，10 年有效，SAN 自动写入 `localhost`、`pos.home.arpa`、`127.0.0.1` 和当前所有局域网 IP）。主机 IP 变了会自动重签，不用手动处理。
- 手机首次打开 https 会提示「证书不受信任 / 连接不是私密连接」：点「高级 → 继续前往」，之后同一浏览器不再提示。这是自签证书的正常现象，因为系统完全离线、没有公共 CA。
- 后台「设置」页和入口页 `/` 上的二维码编的是 **https 地址**，手机扫一下即可进入收银台，无需记 IP 和端口。
- 安卓 Chrome 下 http 页面调用摄像头会直接失败（`navigator.mediaDevices` 为 `undefined`），收银台检测到这种情况会在扫码弹窗里提示改用 https 地址，并保留手动输入条码。
- 没有 `BarcodeDetector` 的浏览器（多数安卓 Chrome）会自动加载内置离线的 ZXing（`web/js/vendor/zxing.min.js`），以「兼容模式」逐帧解码，识别稍慢但可用，全程不联网。

## 功能

### 收银台 `/pos`（无需登录）

- 商品网格、分类筛选、名称/条码搜索
- **扫码枪**（USB HID 免驱，键盘楔入型，扫完自动加入购物车）
- **摄像头扫码**（手机用，需通过 https 打开）：有 `BarcodeDetector` 走原生识别；没有则自建取帧循环 + 内置离线 ZXing（先解中间取景框、再整帧兜底，`TRY_HARDER`），弹窗里会显示已取帧数；http 地址下会提示改用 https，并保留手动输入条码
- 购物车：折叠时底栏显示「合计 + 共 N 件 · 查看明细 ▲」，点合计区域或该行即展开整单明细（单品金额、数量增减、优惠/挂单/取单），再点一次收起
- 整单折扣、抹零、挂单/取单
- 结算：现金（自动算找零，带 10/20/50/100 快捷键与「整付」）、微信、支付宝、银行卡、**组合支付**
- 小票预览与打印（58/80mm，浏览器打印）
- 交接班：开班填备用金，交班自动算应有现金与差额
- 断网提示：主机连不上时顶栏显示「离线」并变红，商品走本地缓存仍可浏览；缓存为空时明确提示离线不可用

### 管理后台 `/admin`（管理员密码）

- 工作台：今日营业额/订单/客单价、7 日趋势、支付占比、库存预警
- 商品：一品多码、分类、进价售价、库存预警值、批量导入导出、行内**删除**（无销售记录的真删，有引用的自动下架）
- 库存：入库/出库/报损/盘点、库存流水、成本统计
- 订单：明细、重打小票、**整单退货（红冲）**
- 设备：改名、6 位设备码、权限开关（改价/退货/库存/折扣上限）、停用
- 报表：支付方式、设备排行、热销 TOP10、每日汇总，3 种 CSV 导出
- 设置：店铺信息、小票页脚、负库存策略、自动打印、改密码、备份/恢复、**初始化 / 清空数据**（自动先备份）；顶上直接显示**手机访问地址 + 二维码**（自动识别本机局域网 IP，可复制、可扫码）

## 数据与备份

- 数据库：`data/pos.db`（WAL 模式，另有 `-wal` / `-shm`）
- 金额全部以「分」存整数，不会出现浮点误差
- 库存只记流水（`inventory_movement`），任何变动可追溯
- 备份：后台「设置 → 下载备份」，或直接调用 `GET /api/admin/backup`（服务端用 `VACUUM INTO` 生成一致性快照，**不要直接复制 pos.db**，WAL 未合并会拿到残库）
- 恢复：上传 `.db` → 系统校验 SQLite 头 → 暂存为 `pos.db.pending` → **重启服务**后自动替换（旧库保留为 `pos.db.bak-时间戳`）
- 建议：每天收盘点一次备份，把文件拷到 U 盘或另一台电脑

## 初始化 / 清空数据

后台「设置 → 初始化 / 清空数据」卡片（接口 `GET /api/admin/system/stats`、`POST /api/admin/system/reset?demo=true|false`）：

| 操作               | 会做什么                                                                                                             | 不会做什么                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 刷新统计           | 读取商品 / 分类 / 订单 / 设备 / 库存流水 / 挂单 / 交接班条数与库文件大小                                             | 不改数据                               |
| 清空所有数据       | 先 `VACUUM INTO backup/pos-before-reset-<时间>-毫秒>.db` 备份，再清空全部业务表、重置设置默认值、重建 3 个默认分类 | **管理员密码保留**；备份文件不删 |
| 清空并写入演示商品 | 同上，另写入 6 个演示商品（条码 `6900000000001`~`…006`，`demo=1`），方便先熟悉界面                            | 同上                                   |

- 两个按钮都会弹二次确认，确认后才执行，执行中按钮置灰防重复点
- 重置后：设备列表清空，手机端需重新命名设备；报表、订单、库存流水从零开始
- 备份名带毫秒，连续两次重置不会因「文件已存在」失败
- 想留真实数据，就别点这两个按钮；只删个别商品用商品行右侧的「删除」（有 `order_item` 引用的会自动降级为下架，其余物理删除并存档条码解绑）

## 绿色版打包（免安装）

双击根目录 `打包绿色版.bat`，产出：

```
dist\POS收银绿色版\      pos.jar / web / jre / 启动.bat / 停止服务.bat / 使用说明.txt
dist\POS收银绿色版.zip   ≈ 75 MB
```

脚本做的事：缺 jar 就先 `mvn package` → 组装 `dist\POS收银绿色版\` → 有 `jlink` 时用 `java.se,jdk.unsupported,jdk.crypto.ec` 生成精简 `jre\`（约 28 MB，OpenJDK 17）→ `Compress-Archive` 打包 zip（同名先删再压）。

使用方式：解压到任意目录（**不要放 C 盘系统目录**），双击 `启动.bat`：

- 优先用包内 `jre\bin\java.exe`（目标机器不用装 Java）；没有 jre 才回退系统 Java
- 首次运行自动建 `data\`、`backup\`，生成 `tls.p12` 自签证书
- 窗口里打印本机 / 后台 / 手机三个地址，5 秒后自动开浏览器
- 停止：关窗口、Ctrl+C，或双击 `停止服务.bat`（按 8080 监听 PID `taskkill`）
- 迁移：整个文件夹拷走即可，数据只在 `data\pos.db` 一个文件里
- 想换端口 / 加参数：手动 `jre\bin\java.exe -jar pos.jar --server.port=8081`（8443 固定，被占用会导致启动失败）

## CSV 导入格式

表头（顺序不限，缺列按空处理），编码 UTF-8：

| 名称           | 分类 | 条码          | 单位 | 进价 | 售价 | 库存 | 预警值 |
| -------------- | ---- | ------------- | ---- | ---- | ---- | ---- | ------ |
| 农夫山泉 550ml | 饮料 | 6900000000001 | 件   | 2.00 | 2.50 | 50   | 5      |

- 价格单位是**元**，可带两位小数
- 条码已存在则更新该商品，否则新建
- 分类不存在会自动创建

## 常见问题

**手机打不开页面**

1. 确认手机和主机在同一 Wi-Fi（不要连访客网络）
2. `ipconfig` 查看主机 IPv4，用它替换 `localhost`
3. 防火墙放行端口：右键 `放行防火墙端口.bat` →「以管理员身份运行」（放行 8080 与 8443）
4. 主机睡眠会断连，电源设置里把睡眠设为「从不」

**手机摄像头扫码用不了**

1. 地址必须是 `https://本机IP:8443/pos`，http 的 8080 在安卓下会被安全策略拦住，弹窗里会提示
2. 首次打开 https 要点「继续前往」信任自签证书，否则摄像头和接口都可能被拦
3. 安卓 Chrome 里不要开「私人 DNS / 安全 DNS」到不存在的域名，否则整个局域网地址都解析失败
4. 浏览器没有摄像头权限被拒过：到「网站设置 → 摄像头」里改回「允许」，或换个浏览器重试

**能看到画面，但一直不自动识别**

- 弹窗里只有一行状态：`把条码放进框里` → 识别循环跑起来后变成 `正在识别… 已取 N 帧`。帧数不涨说明摄像头没真正出画（先查是否用的 https、权限是否允许）；帧数在涨却不出结果，通常是下面几件事：
  1. 条码没进中间取景框，或离太近导致对焦糊——退到 15~25cm，让整条条码横向铺满框
  2. 光线太暗 / 反光——条码两侧的空白必须能看见，别只露黑白条
  3. 条码本身破损、褶皱、屏幕贴膜反光，或者弯折曲面瓶身上的条码严重变形
  4. 商品条码是店内自编码（非标准 EAN-13/UPC），ZXing 需要完整校验位，可以改用「手动输入条码」或扫码枪
- 已支持的格式：EAN-13、EAN-8、UPC-A、UPC-E、Code 128、Code 39、Code 93、ITF、QR。开了 `TRY_HARDER`，识别偏慢属于正常。
- 设备只暴露 `BarcodeDetector` 接口、没有解码服务时（Windows Chrome、部分安卓会抛 `Barcode detection service unavailable`），代码会自动跳过原生识别、切到内置 ZXing，界面上看不出区别，也不再有「诊断」按钮。
- 实在扫不出：弹窗里的输入框直接手输条码，回车即入车。

**`start.bat` 报「'本机:' 不是内部或外部命令」**

- 旧版脚本保存成了 **UTF-8 带 BOM**，BOM 让首行 `@echo off` 失效、命令被逐行回显并解析异常。当前版本已重写为 **UTF-8 无 BOM + CRLF**，该行报错不会再有。
- 用记事本改过 `.bat` 后如果又出问题，另存为时选「UTF-8（无 BOM）」或在 PowerShell 里执行：`[IO.File]::WriteAllText($p,$txt,(New-Object Text.UTF8Encoding $false))`。

**重复启动 `start.bat` 提示端口占用**

- 说明服务已经在跑（可能是 `start-service.bat` 或开机自启的计划任务 `POS-Server` 起的）。
- 直接访问 `http://localhost:8080` 即可；要重启就先运行 `停止服务.bat`，再运行 `start.bat`。

**扫码枪没反应**

- 需为「键盘楔入 / HID」型，插上后光标在收银页直接扫即可
- 若扫出来是乱码，检查扫码枪的输出编码设为 UTF-8、结尾字符设为回车

**打印小票**

- 浏览器打印对话框里选小票打印机，边距设为「无」，缩放 100%
- 也可在设置里开启「收款后自动打印」

**换电脑 / 重装**

- 整个目录拷走（至少 `backend/target/pos.jar`、`web/`、`data/`）
- 或只拷 `data/pos.db` 到新机器同路径

**改端口**

- 启动前设置环境变量 `SERVER_PORT=8090`，或改 `backend/src/main/resources/application.yml`

**多台收银机同时用会不会冲突**

- 所有写操作走同一个服务进程与事务，库存不会打架；SQLite 单写连接足以支撑 5 台终端

## 技术要点

- Spring Boot 3.3 + JdbcTemplate + SQLite（单连接池，`busy_timeout=5000`，WAL）
- 结算事务：订单 + 明细 + 支付 + 库存流水 + 库存快照，一次提交，失败全回滚
- 退货：生成负数红冲单，原路负数支付记录，库存回补；报表按净额统计
- 设备身份：浏览器生成 UUID，存 localStorage + IndexedDB 双份，请求头 `X-Device-Id` 带上来
- 后台鉴权：登录换 token，`X-Admin-Token` 校验，12 小时过期
- 二维码：`GET /api/qr.png?text=&size=`，服务端 ZXing 现画，不依赖任何在线服务
- HTTPS：8080 之外附加 8443 连接器；启动时用 BouncyCastle 生成自签 X.509（`data/tls.p12`），SAN 写入所有 LAN IP，IP 变化后自动重签，Tomcat 通过 `SSLHostConfig + SSLHostConfigCertificate` 挂载
- 扫码：优先 `BarcodeDetector`，但启动时**先调用一次 `detect()` 做探测**——设备只暴露接口、没有解码服务时会抛 `Barcode detection service unavailable`，此时立刻置空 detector 并落到内置 ZXing（运行时再报同类错误同样自动降级），避免每帧空转、永不识别；ZXing 用本地打包的 `@zxing/library`（`web/js/vendor/zxing.min.js`），纯离线；不用库自带的 `decodeFromVideoElement`（默认 hint 少、按整帧高分辨率解码，手机上几乎识别不到），改成自己 `drawImage` 抓帧 → `HTMLCanvasElementLuminanceSource` → `HybridBinarizer` → `MultiFormatReader.decode`，并开 `TRY_HARDER` + 限定 9 种常见条码格式
- 扫码弹窗只留一个取景区：一行状态提示（`把条码放进框里` / `正在识别… 已取 N 帧`）+ 「相册识别」+ 手输输入框；诊断面板和预览小画布已移除
- 后台「新增 / 编辑商品」的条码框旁有 **「扫码」** 按钮，走同一套离线扫码实现（`web/js/scan.js`，独立于收银端）：先探 `BarcodeDetector`，不可用自动降级 ZXing，解出的码追加进逗号分隔的条码列表（重复不叠加），也支持「相册识别」。手机端后台要开摄像头同样得用 https 访问
- 条码唯一：保存商品时列表内自动去重；同一条码若已被别的商品登记，会自动从旧商品解绑并在新商品上登记；启动时清理库里的重复条码（同码只留最早一条）和指向已删商品的孤儿条码
- 条码防 Excel 数字截断：导出的 CSV 把条码写成 `="6901209279126"` 形式（Excel 里保持文本），导入时再剥掉 `="` 包裹、前导单引号，并把 `6.02E+12` 这类科学计数法还原成整数串，同时在导入结果里列出「已还原，请核对位数」的提醒（精度本身无法找回，只能重新导一次原条码）
- 商品删除：`DELETE /api/admin/products/{id}` 会先查 `order_item`，没卖过的物理删除（连条码、库存快照一起删），卖过的只下架，保证历史订单和报表还能读到商品名；后台商品列表每行都有「删除」按钮，删除前二次确认
- 初始化：`SystemApi` 先 `VACUUM INTO backup/pos-before-reset-yyyyMMdd-HHmmss-SSS.db`（毫秒级文件名防同一秒冲突），再用一个事务清空 13 张业务表与 `sqlite_sequence`、写回 `settings` 默认值、重建 3 个默认分类；`demo=true` 时在同一事务里插 6 个演示商品和对应入库流水。管理员密码在另一张表里，不受影响
- 绿色版：`打包绿色版.bat` = 编译 → 拷 `pos.jar/web/启动.bat/停止服务.bat/使用说明.txt` → `jlink --add-modules java.se,jdk.unsupported,jdk.crypto.ec` 生成精简 JRE → `Compress-Archive`。`启动.bat` 先查 `%~dp0jre\bin\java.exe`，找不到才用系统 Java，运行前自动建 `data`/`backup`
