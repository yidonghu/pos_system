# 多门店收银系统 方案 v1

> 定位：面向国内便利店 / 小超市 / 母婴 / 烟酒 / 生鲜零售的轻量收银系统。
> 两套前端（PC 管理后台 Web + 移动端 H5），一套后端，支持断网收银、多门店、库存联动、扫码枪、数据导入导出。



***

## 一、需求拆解与边界



| 需求       | 落地方案                                                 | 边界说明                                |
| -------- | ---------------------------------------------------- | ----------------------------------- |
| PC 端管理后台 | Vue 3 单页应用，桌面优先（≥1366×768 自适应）                       | 不做桌面客户端（EXE），浏览器直接访问                |
| 移动端      | 同一套后端 + 响应式 H5，手机竖屏收银、安卓自助收银机横屏 kiosk                | 手机用浏览器访问，不装 App；可 "添加到主屏幕" 当类 App 用 |
| 多门店管理    | 总部 — 门店两级：门店档案、独立库存、独立价格、店员工交班、汇总报表                  | 本期不做加盟分账、跨主体结算                      |
| 离线使用     | 本地优先写库 + 增量同步（详见第六章）                                 | 离线期间**不接真实支付通道**，仅记账                |
| 门店收银     | 扫码 / 手输条码、商品检索、称重、挂单、退货、整单折扣、抹零、交班                   | 不做餐饮的 "桌台 / 加菜 / 厨打"，以零售商品为主        |
| 支付记账     | 现金 / 微信 / 支付宝 / 银行卡 / 会员储值 / 组合支付                    | **默认只记账，不对接支付接口**；后续可加聚合收款码（需商户资质）  |
| 库存检测     | 实时库存、安全库存预警、负库存拦截、盘点、调拨、报损、出入库流水                     | 不做多仓 / 批次 / 保质期（可作为二期）              |
| 扫码枪      | USB HID 免驱（键盘模拟），Web 端捕获按键流 + 前后缀规则                  | 需要键盘楔入型扫码枪；串口 / 蓝牙枪需厂商 SDK，本期不支持    |
| 数据导入导出   | 商品 / 会员 Excel 导入（模板 + 校验报告）、订单 / 库存 / 报表导出 Excel/CSV | 单次导入上限 5000 行，超出走分批                 |
| 界面风格     | 现代扁平、高信息密度、大触控目标（详见第八章）                              | 主色不走紫色系                             |

**规模假设**（用于容量设计，如有差异需调整）：门店 ≤ 10 家、单店 SKU ≤ 3000、单店日单量 ≤ 500、终端 ≤ 4 台 / 店。

## 二、技术选型



| 层次      | 选型                                                   | 理由                      |
| ------- | ---------------------------------------------------- | ----------------------- |
| PC 后台   | Vue 3 + TypeScript + Vite + Pinia                    | 生态成熟、构建快、可复用组件到移动端      |
| PC UI 库 | Element Plus（做主题变量定制，不直接用默认蓝）                        | 表格 / 表单能力强，改主题成本低       |
| 移动 UI   | Vant 4 + 自研收银数字键盘、商品瀑布流                              | 触控友好，包体小                |
| 本地存储    | Dexie.js（IndexedDB）+ Service Worker（Workbox）         | 浏览器原生、可存万级数据、支持事务       |
| 后端      | Spring Boot 3.x + Java 17 + MyBatis-Plus             | 与既有技术栈一致，单 jar 可跑店内节点   |
| 云端数据库   | MySQL 8                                              | 报表聚合、多门店汇总              |
| 门店节点数据库 | SQLite（WAL 模式）                                       | 单文件、零运维，Windows 小主机即可承载 |
| 鉴权      | JWT（终端设备令牌 + 员工登录双因子）                                | 离线时可用本地令牌校验             |
| 接口      | REST + 幂等键（`Idempotency-Key`）                        | 断网重试不重复下单               |
| 打印      | 58mm/80mm 小票，浏览器 `window.print` + 本地打印代理（可选 ESC/POS） | 免装驱动方案优先                |
| 部署      | 云端 Docker Compose；店内节点 = 一键脚本安装的 Windows 服务          | 双击即装，符合现场部署习惯           |

> 关于 Flutter：移动端若用 Flutter Web，首屏包体 3–5MB、PWA 冷启动与离线缓存弱、收银键盘与小票打印适配成本高。本期移动端用 Vue 响应式 H5 更划算；Flutter 更适合后期做原生自助机 App。

## 三、总体架构



```
┌────────────────────────── 云端（阿里云/腾讯云 或 自建）──────────────────────────┐
│  Spring Boot 云端服务  ·  MySQL 8  ·  对象存储(商品图/导出文件)                    │
│  职责：总部后台、跨店汇总报表、主数据下发、同步服务、备份                          │
└───────────────▲──────────────────────────────────────────▲──────────────────┘
                │ 增量同步（HTTPS，断网自动重试）              │
┌───────────────┴──────────────┐              ┌──────────────┴──────────────┐
│ 门店 A 节点（Windows 小主机） │              │ 门店 B 节点                  │
│  Spring Boot 本地服务         │              │  ...                        │
│  SQLite：订单/库存/商品镜像    │              │                             │
│  局域网 IP：192.168.1.20:8080 │              │                             │
└───────▲──────────▲───────────┘              └─────────────────────────────┘
        │ 店内 Wi-Fi（外网断了也不影响）
┌───────┴────┐ ┌────┴─────┐ ┌────┴──────┐
│ 收银 PC     │ │ 手机浏览器│ │ 自助收银机 │
│ (Chrome)    │ │ (PWA)    │ │ (安卓横屏) │
└─────────────┘ └──────────┘ └───────────┘
```

**两条链路同时存在**：终端 → 店内节点（毫秒级响应，断外网可用）→ 云端（联网时补传）。这是 "真离线" 和 "纯浏览器缓存" 的区别：前者库存是单一权威源，不会多设备超卖。

## 五、数据模型（核心 12 表）



| 表                       | 关键字段                                                                                                                                   | 说明                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `tenant`                | id, name                                                                                                                               | 商户主体               |
| `store`                 | id, tenant\_id, name, address, node\_url, status                                                                                       | 门店 + 节点地址          |
| `device`                | id, store\_id, name, type(pc/phone/kiosk), token                                                                                       | 终端授权               |
| `user` / `role`         | id, store\_id, phone, password\_hash, role\_code                                                                                       | 员工与角色              |
| `product`               | id, name, category\_id, unit, is\_weight, cost\_price, sale\_price, member\_price, status                                              | 金额字段全部 `int`（单位：分） |
| `product_barcode`       | product\_id, barcode, is\_primary                                                                                                      | 一品多码               |
| `inventory_movement`    | id, store\_id, product\_id, type(in/out/sale/return/adjust/transfer/check), qty, unit\_cost, ref\_no, occur\_at, device\_id            | **库存唯一事实来源**（事件流）  |
| `stock_snapshot`        | store\_id, product\_id, qty, updated\_at                                                                                               | 由流水汇总的快照，仅用于加速查询   |
| `order`                 | id, order\_no, store\_id, device\_id, cashier\_id, total\_amount, discount, round\_off, pay\_status, shift\_id, occur\_at, sync\_state | 订单主表               |
| `order_item`            | order\_id, product\_id, barcode, qty, price, amount                                                                                    | 明细                 |
| `payment`               | order\_id, method(cash/wechat/alipay/bank/member), amount, trade\_no, status                                                           | **一单多笔**，支持组合支付    |
| `member` / `member_txn` | phone, balance, points / member\_id, type, amount                                                                                      | 储值流水               |
| `shift`                 | store\_id, user\_id, start\_at, end\_at, cash\_expected, cash\_actual, diff                                                            | 交班对账               |
| `sync_outbox`           | id, entity, op, payload, idempotency\_key, retry\_count, status, created\_at                                                           | 上行队列（终端与节点各一份）     |

**三条硬规则**



1. **金额只用整数分**（`int`/`long`），前端展示时格式化，杜绝浮点误差。

2. **库存不写绝对值**，只追加流水；任何库存变化都能追溯到单据。

3. **主键用雪花 ID + 设备前缀**，离线生成不撞号；订单号用 `店号-设备号-YYYYMMDD-序号` 便于人读与小票。

## 六、离线与同步（本方案的核心）

### 6.1 写入路径（本地优先）



```
收银动作 → 终端 IndexedDB 事务提交（订单+明细+支付+库存流水+outbox 一条）
        → 立即出小票、购物车清空（无网络等待）
        → 后台把 outbox 推给店内节点（局域网内通常 <200ms 即成功）
        → 店内节点再推给云端
```

### 6.2 同步协议



| 项目 | 设计                                                                                            |
| -- | --------------------------------------------------------------------------------------------- |
| 上行 | `POST /sync/push`，批量 ≤ 50 条，每条带 `idempotency_key`；服务端逐条返回 `ok / duplicate / conflict / error` |
| 下行 | `GET /sync/pull?cursor=<updated_at>`，拉取商品、价格、会员、库存快照变更                                        |
| 重试 | 指数退避 5s → 15s → 60s → 5min，最多 12 次后转人工队列                                                      |
| 去重 | 服务端对 `idempotency_key` 建唯一索引，重放直接返回已有结果                                                       |
| 顺序 | 同一终端的队列**串行**发送，保证单号递增语义                                                                      |

### 6.3 冲突策略



| 数据类型    | 策略                                     |
| ------- | -------------------------------------- |
| 订单 / 支付 | 只增不改。退货生成红冲单，绝不修改原单 → 天然无冲突            |
| 库存      | 按流水合并求和，不覆盖绝对值 → 多终端同时卖也能算对            |
| 商品主数据   | 云端为准。云端改价下发；本地有未同步改价则保留两份并记冲突日志，后台人工裁决 |
| 会员储值    | 以流水合并（充值 +/ 消费−），余额 = 汇总值，避免余额覆盖导致丢钱   |

### 6.4 兜底



* 每日 02:00 云端对账任务：比对各店订单数、销售额、库存差异，差异 >0 自动告警。

* 节点数据库每小时自动备份到云端对象存储，保留 30 天。

* 终端 "离线待同步" 超 8 小时未清空 → 后台红灯提示。

| # | 事项                      | 当前默认              | 影响                            |
